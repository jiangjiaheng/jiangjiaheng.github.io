      # 系统核心

      这个模块是整个操作系统的底层规则。

      它只回答三个问题：

      1. 我往哪里走
      2. 我怎么走
      3. 哪些边界不能突破

      # 核心立场

      # 1. 保守主义是方向

      保守主义不是停滞，而是优先信任被时间和现实反复验证过的结构。

      默认判断：

      • 稳定比刺激重要
      • 秩序比情绪重要
      • 长期比短期重要
      • 可持续比爆发重要

      这些判断是为了守住基本盘，不是为了把路径固定下来。环境变了，经验也需要重新验证。

      # 2. 效率主义是方法

      效率不是压榨自己，而是保护有限资源。

      过去我习惯追求结果最优解：从结果上看接近 90 分，甚至看起来完美。

      但结果最优的解法，往往也是综合成本最高的解法。

      好的方法应该：

      • 成本更低
      • 更容易执行
      • 更容易复用
      • 更不依赖意志力

      所以效率主义的核心不是把每件事做到最好，而是在时间、精力和金钱的总成本里，找到真正划算的解法。

      省下来的时间也不必全部投入下一件事。技术负责提高效率，我负责决定把余量用在工作、生活还是休息上。具体怎样留出余量，放在身心稳定里讨论。

      # 3. 创作型人生是长期方向

      体验不是错误，但对消费和刺激的追逐不能成为系统中心。

      长期方向是从体验型人生转向创作型人生：

      • 少一点消费和刺激
      • 多一点输出和构建
      • 少一点短期满足
      • 多一点长期积累

      这仍然是我愿意保留的方向。但创作和积累也要服务于生活，不能反过来要求生活里的每一刻都有产出。

      健康、真实的关系、线下体验和自由时间，本身就值得保留，不必先证明它们对创作有什么帮助。

      # 4. 手段不能取代目的

      我越来越觉得，生活里稀缺的东西正在变化。

      知识、娱乐、交流和数字工具越来越容易获得，AI 又让一些认知工作变得更便宜。但我的注意力、睡眠和恢复时间，并没有因此增加。

      过去容易沿着“努力 → 工作 → 挣钱 → 积累物质”一直走。现在我还需要问：这些积累有没有换来更好的健康、生活、体验和自由？

      物质基础仍然重要，只是不能用它代替全部生活目标。工作、金钱、效率、自律和计划，都是支撑生活的手段。

      # 判断顺序

      在开始分析之前，我需要先问一句：

      这真的是一个需要解决的问题吗？

      过去我习惯发现问题以后直接进入解决流程，再确认它彻底结束。现在更想先看清：现实中发生了什么，它影响了什么，我想要的结果又是什么。

      有时问题定义错了，有时只是原来的要求已经不适合现在的生活，还有时根本不需要介入。

      工兵拿到问题以后想“怎么解决”；设计者或总工程师还要先想“为什么要解决，有没有其他路径”。我需要的不只是把任务做好的能力，也包括决定哪些任务值得做的能力。

      确认需要处理之后，再按下面的顺序判断。

      # 1. 人性优先

      人性不会因为理性更强就消失。

      趋利避害、损失厌恶、虚荣、懒惰、比较、短期诱惑，都是长期存在的底层结构。

      系统设计不能假装人性不存在。

      # 2. 经验优先

      现实里反复验证过的经验，比纯逻辑推演更可靠。

      推演可以辅助判断，但不能替代现实反馈。

      # 3. 理性负责调整

      理性的职责不是审判感受，也不是消灭人性。

      理性应该负责：

      • 分析局部问题
      • 权衡利弊
      • 调整路径
      • 设计规则
      • 降低系统风险

      # 运行规则

      # 1. 60分原则

      能稳定落地的 60 分，通常比高成本追求 90 分更有价值。

      默认规则：

      • 完成优先于完美
      • 够用之后停止优化
      • 只有额外成本很低时才继续提升
      • 理想化方案如果无法执行，实际价值就是零

      判断事情能否结束时，我只需要问两个问题：

      1. 事情有没有结果？
      2. 这个结果还需不需要我处理？

      有结果，而且不需要我继续处理，就可以结束。

      不必为了认知上的完整，再检查过程是否完美、弄清所有细节、排除所有理论风险。必要的核实和后续责任做完，剩下的不确定性可以留着。

      如果未来真的出现新的影响，就把它作为新的现实问题处理。事情结束了，感受却还没跟上，是身心稳定里需要面对的另一件事。

      # 2. 成本最优原则

      确认问题值得处理之后，优先追求成本最优解，而不是结果最优解。

      成本包括：

      • 时间成本
      • 精力成本
      • 金钱成本
      • 情绪成本
      • 后续维护成本

      有些方案从结果上看不够完美，但如果它低消耗、可执行、能解决主要问题，它就是更适合系统的方案。

      默认规则：

      • 先问成本，再看结果
      • 不为 90 分结果支付过高成本
      • 能用低成本解决的问题，不升级成高成本问题
      • 解决主要矛盾之后，允许结果不完美

      # 3. 连续性原则

      长期稳定来自持续，而不是爆发。

      系统风险不按平均值结算，而按最坏一天结算。

      默认规则：

      • 允许慢
      • 不允许失控
      • 不用一次性消耗换未来免维护
      • 当效率和连续性冲突时，选择连续性

      # 4. 区间原则

      现实里的确定性不是一个点，而是一个区间。

      涉及不确定系统时，先预设可接受范围：

      • 时间区间
      • 结果区间
      • 风险区间
      • 行动频率

      结果在区间内，不追加情绪判断；超出区间，再分析和干预。

      # 5. 分工原则

      个人不是闭环系统。

      不是所有事都应该自己扛。

      先判断：

      1. 这件事是否需要专业能力
      2. 是否必须由我亲自完成
      3. 是否可以交给协作、工具或系统

      拒绝亲力亲为幻觉。

      # 6. 计划服务于人

      计划是按当时的条件做出的安排。现实变了，计划也应该允许变化。

      对我来说，困难有时不在于不知道该调整，而在于改变计划本身就会不舒服，甚至身体也会跟着紧绷。

      这种路径依赖未必马上消失。我可以修改安排，也允许修改之后的不舒服暂时存在，不必等到完全舒服才调整。

      连续性要保留的是长期方向，不是每天照原计划执行。计划被打破，不等于生活出了问题。

      # 从现实中更新方法

      # 1. 纵向做深，也要横向尝试

      逻辑、规划、自律、坚持、优化和风险控制，都是把一件事越做越好的纵向能力。

      但只有纵向能力，也可能让我在一个错误或并不重要的方向上越做越好。

      横向能力是接触陌生领域、尝试新东西、改变路径，给自己增加选择。它不能只停留在“我要更开放”的口号里。

      在成本和风险可接受的范围内，实际试一次：喜欢，就多了一个选择；不喜欢，也排除了一个选择。这次尝试已经带回了思考本身给不了的信息。

      思考 → 尝试 → 现实反馈 → 修正认知 → 增加选择。

      横向尝试帮助我选择方向，纵向积累帮助我在值得的方向上走下去。

      # 2. 现实没有永久有效的攻略

      规则基本固定的游戏，一份攻略可能很多年以后仍然有用。现实不同，环境、工具和人与人的关系都在变化，过去有效的策略不一定一直有效。

      参考经验，也要看经验成立的条件还在不在。方法需要持续更新，但不必因为出现新东西就全部推翻。

      AI 就是一个例子。我未必需要研究大模型或成为 AI 专家，但需要知道这个时代多了什么能力，能不能拿来解决自己的实际问题。用一次，看结果，再决定是否留下。

      # 3. 思考可以复杂，执行应该简单

      理解一件事时，可以考虑很多因素。到了行动时，不必把整套分析都背在身上。

      眼前值得做，就做一个具体动作；缺少现实信息，就做一次小尝试；需要等待，就先回到生活；已经结束，就停止处理。

      系统越完整，越应该让我少一点临场纠缠，而不是给日常生活增加更多检查。

      # 系统边界

      • 不为短期情绪高峰牺牲长期稳定
      • 不接受不可撤回、不可验证的高风险押注
      • 不用爆发式消耗换表面进步
      • 不透支身体和睡眠
      • 不在高情绪状态下做重大决定

      # 一句话总结

      系统核心是：守住基本盘，让方法随现实调整，让工具服务于生活。
